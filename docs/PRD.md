## 1. 背景与机会
MiroFish 是一个开源的多智能体群体仿真预测引擎，通过"种子材料 → 知识图谱 →
批量 Agent 生成 → OASIS 双平台模拟 → 结构化报告"的五阶段流水线，对舆情演化、
政策反应、金融情绪等问题做群体级 what-if 推演，并支持运行中的"上帝视角"变量注入。
原项目存在三个使用门槛：
1. Web 层为 Flask + Vue 前后端分离，部署重、定制难；
2. Agent 长期记忆依赖 Zep Cloud，数据出境且产生持续费用；
3. 缺少多任务管理、成本控制和团队协作能力。
本项目定位：**基于 MiroFish 引擎，构建一个可自托管的 Web 化仿真推演平台**，
面向内部团队提供从任务创建、过程观摩到报告产出的完整闭环。
## 2. 产品目标（示例值，评审时定稿）
| 指标 | 目标 |
|---|---|
| 端到端可用性 | 上传材料到产出报告全流程无人工干预跑通 |
| 单任务规模 | 一期支持 20–50 个 Agent、10–30 轮模拟稳定运行 |
| 过程可观测 | 模拟事件产生到前端展示延迟 < 3 秒（SSE） |
| 成本可控 | 每任务设预算硬上限，超限自动暂停并告警 |
| 数据主权 | 图谱、记忆、模拟事件全部存储于本地 PostgreSQL/Redis，不依赖 Zep Cloud |
**定位声明**：本平台的输出是"推演"而非"预测"。报告页必须显著标注
"基于当前输入的仿真推演结果，属待验证假设"，不做准确率承诺。
## 3. 用户与角色

## 5. 核心流程说明
### 5.1 任务创建流程
1. 用户进入 `/tasks/new`，上传 1–N 份种子材料；
2. 填写推演问题（必填，10–500 字）；
3. 设置参数：Agent 数（默认 30，上限一期 50）、轮数（默认 20）、
   预算上限（默认 ¥20，可改）；
4. 提交后任务进入 `queued` 状态，由 arq Worker 接管。
### 5.2 模拟执行流水线（Worker 内部）
```
queued → building_graph → generating_agents → simulating → generating_report → done
              │                  │                 │               │
              └──── 任一阶段失败 → failed（记录错误原因，可重跑）┘
```
- 每阶段完成即刻更新任务进度与 Redis 进度键；
- 模拟阶段逐事件写入 `simulation_events` 表并发布到 Redis PubSub；
- 每阶段结束记录累计 token 消耗，超出预算 → 置为 `paused_budget`，通知用户。
### 5.3 上帝视角变量注入
1. 用户在直播页输入注入内容（如"突发：监管新规发布"）；
2. FastAPI 写入 Redis 注入队列；
3. Worker 在下一轮开始时消费并注入 OASIS 环境；
4. 注入事件在事件流中以特殊样式标记，保证可追溯。
### 5.4 知识库替代方案说明
原版 MiroFish 使用 Zep Cloud 做 Agent 长期记忆。本项目改用
LlamaIndex PropertyGraphIndex + PostgreSQL 本地存储，Agent 记忆以
`graph_nodes / graph_edges / agents.memory_summary` 承载，不外发任何数据。
## 6. 非功能需求
| 类别 | 要求 |
|---|---|
| 性能 | 页面接口 P95 < 500ms；SSE 事件延迟 < 3s |
| 并发 | 一期支持 2 个模拟任务并行（受单机 LLM API 限流约束） |
| 可靠性 | Worker 崩溃后任务可从最近阶段恢复（事件表 + 进度键） |
| 安全 | 全站 JWT 鉴权；上传文件类型/大小白名单校验（≤ 20MB） |
| 审计 | 变量注入、任务终止等敏感操作记录操作日志 |
## 7. 明确不做（本期范围外）
- ❌ 面向公网的 SaaS 多租户（AGPL-3.0 协议下对外提供服务需开源修改部分，
  一期仅内部使用）
- ❌ 微信 / 企业微信 / 移动 App 渠道
- ❌ 自研模拟引擎（直接复用 OASIS / MiroFish 引擎层）
- ❌ 实时人工接管对话
- ❌ 准确率承诺或预测结果背书
## 8. 约束与技术决策记录
| 决策 | 内容 | 理由 |
|---|---|---|
| D1 | Web 框架 FastAPI，入口 main.py 在根目录 | 延续既有项目结构 |
| D2 | 前端 Jinja2 + HTMX + Alpine.js + ECharts，无 Node 构建链 | 单机轻量部署、技术栈统一 |
| D3 | 任务队列 arq（asyncio 原生） | 与 FastAPI 异步模型契合，比 Celery 轻 |
| D4 | 图谱/记忆用 LlamaIndex 本地实现 | 替代 Zep Cloud，数据主权 |
| D5 | MiroFish 引擎以 git submodule 方式引入 vendor/ | 隔离上游代码，明确修改边界 |
| D6 | 运行时数据（logs/uploads）写 /var/log 与 /var/lib | 代码目录保持只读 |
| D7 | LLM 走 OpenAI 兼容 API（默认 DeepSeek），Embedding 本地 BGE-M3 | 成本与中文效果平衡 |
## 9. 验收标准
一期（MVP）：
- [ ] 上传一份 ≥ 5000 字的种子文档 + 提问，30 分钟内产出结构化报告
- [ ] 全程零外部 SaaS 依赖（无 Zep / 无托管服务）
- [ ] 模拟事件完整落库，报告含事件脉络、关键节点、趋势判断三节
- [ ] 任务失败后可从失败阶段重跑
- [ ] 预算超限时任务自动暂停并产生告警记录
- [ ] 在 Debian 13 上通过 systemd 部署，连续运行 72h 无人工干预
二期：
- [ ] 沙盘直播页事件延迟 < 3s，页面刷新后可续看
- [ ] 变量注入后，下一轮事件流可见注入生效标记
- [ ] 图谱可视化节点数 ≥ 200 不卡顿（虚拟滚动或分页加载）
- [ ] 与 Agent 对话响应流式输出，首 token < 2s
